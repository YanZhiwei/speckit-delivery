# Independent review profile

Owner: Review's coordinator and the installed
`.specify/extensions/review/templates/reviewer.md`. That template owns scope,
snapshot identity, six dimensions, findings, coverage, independence, aggregation,
and the native report. Use the shared method adapter contract without dispatching
another reviewer from this reviewer context.

1. Read the coordinator's exact requirements/design/constraint packet, full scope
   diff (including relevant uncommitted contents), callers, verification receipts,
   and prior findings. Implementer summaries are claims to verify.
2. Check documented standards and requirement coverage as distinct questions.
   Reuse valid exact-scope mechanical/Standards evidence; independently inspect
   concrete defects, interfaces, failure paths, and test effectiveness.
3. Trace candidate defects to actual triggers and consumers. Check contrary
   evidence before reporting a blocker. Skill preferences and heuristic smells
   alone do not establish project-rule violations.
4. Return every native review dimension and prior finding disposition, with
   locations, evidence, coverage limits, and the actual snapshot. A source skill's
   two-axis report, commit-only diff, missing finding, or self-declared completion
   cannot replace SD's full report.

Return the native Reviewer report plus method provenance to the coordinator for
validation/persistence. Do not write a report file, fix code, commit, open another
worktree, spawn agents, or park confirmed blockers because a budget expired.
Unresolved required coverage stays incomplete; confirmed blockers stay blocked.
Review's coordinator handles repairs, budget accounting, and any separately
required governance decision. Task review does not replace final integration.

Method provenance: Superpowers' focused reviewer packets/feedback verification
and Matt Pocock's separate standards/spec lenses informed this profile. Optional
specialist guidance follows the same readonly scope and report contract.
